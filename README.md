# GNSS Environmental Monitoring Dataset Processing Code

## 1. Overview

This repository provides the preprocessing and visualization codes for the **GNSS Environmental Monitoring Dataset**.

The purpose of this repository is to provide a reproducible processing pipeline that converts raw GNSS receiver outputs into structured GNSS observation products and satellite-time feature matrices for GNSS signal analysis and propagation-environment sensing applications.

The processing pipeline consists of two main stages:

1. **UBX message decoding and data organization**

   Raw GNSS receiver outputs are decoded and reorganized into structured GNSS files, including:

   - `observation`: raw GNSS measurements;
   - `satelliteInformation`: satellite status and geometry information;
   - `pvtSolution`: positioning-related information.

2. **Satellite-geometry-based alignment and feature matrix generation**

   The structured GNSS observations are aligned using satellite elevation and azimuth information and transformed into satellite-time feature matrices for GNSS signal analysis, environmental sensing, and machine learning applications.

The preprocessing pipeline preserves the original characteristics of GNSS observations. No observation-level quality filtering, including cycle-slip removal, Doppler consistency checking, or pseudorange outlier screening, is applied.

Signal variations caused by real propagation environments, such as multipath, signal blockage, and non-line-of-sight (NLOS) reception, are retained for further analysis.

# 2. Dataset and Processing Workflow

The complete processing pipeline transforms raw GNSS receiver outputs into structured GNSS products and satellite-time feature matrices.

The overall workflow is summarized as follows:

```text
Raw UBX receiver outputs
        |
        v
UBX message parsing
(RXM-RAWX, NAV-SAT, NAV-PVT,
 NAV-POSECEF, NAV-CLOCK, NAV-DOP)
        |
        v
Structured GNSS files
(observation,
 satelliteInformation,
 pvtSolution)
        |
        v
Satellite geometry extraction
(elevation and azimuth information)
        |
        v
Satellite-geometry-based
cross-site alignment
        |
        v
Satellite-time feature matrices
```


## Stage 1: UBX Message Processing

Raw UBX messages are decoded and reorganized according to different message types.

The generated structured files include:

- **observation**

  Contains raw GNSS measurements extracted from `RXM-RAWX`, including:

  - pseudorange;
  - carrier phase;
  - Doppler;
  - carrier-to-noise density ratio (C/N0).


- **satelliteInformation**

  Contains satellite status and geometry information extracted from `NAV-SAT`, including:

  - satellite identifier;
  - visibility status;
  - C/N0;
  - elevation angle;
  - azimuth angle.


- **pvtSolution**

  Contains receiver positioning-related information generated by combining:

  - `NAV-PVT`;
  - `NAV-POSECEF`;
  - `NAV-CLOCK`;
  - `NAV-DOP`.


Different UBX message types are synchronized using the timestamp information contained in each message.

The synchronization process does not depend on the original message ordering. Instead, observations from different UBX message types are associated according to the `recordTime` field.


## Stage 2: Satellite Geometry Alignment and Feature Matrix Generation

The structured GNSS files are further processed to generate comparable satellite-level observations across monitoring sites.

Satellite elevation and azimuth information are extracted to characterize satellite geometry.

The observations from different monitoring sites are aligned according to satellite geometry information. The aligned observations are then reorganized into satellite-time feature matrices, where each satellite corresponds to a time-series observation.

The generated matrices can be used for:

- GNSS signal quality analysis;
- propagation-environment sensing;
- time-series analysis;
- machine learning-based applications.

# 4. Hardware and Raw Data Description

The GNSS dataset was collected using a **u-blox high-precision GNSS receiver**.

The receiver outputs raw UBX messages, including:

- `RXM-RAWX`: raw GNSS measurements;
- `NAV-SAT`: satellite status and geometry information;
- `NAV-PVT`: receiver position, velocity, and time solution;
- `NAV-POSECEF`: receiver ECEF position information;
- `NAV-CLOCK`: receiver clock information;
- `NAV-DOP`: dilution of precision information.


The original receiver observations were recorded at a sampling rate of **1 Hz**.

During preprocessing, different UBX message types are associated using the timestamp information contained in each message.

The `recordTime` field is used as the common reference for epoch-level synchronization.

# 6. Dataset Structure and File Format

The dataset contains:

- **Complete-cycle observations from 12 monitoring sites (S1-S12)** for GNSS signal analysis under different propagation environments.
- **Synchronized observations from three closely located sites (P1-P3)** for comparison of local environmental effects under consistent satellite geometry conditions.


The complete data processing workflow is:

```text
Raw UBX receiver outputs
        |
        v
Process-1.py
        |
        v
Structured GNSS files
(observation,
 satelliteInformation,
 pvtSolution)
        |
        v
Process-2.py
        |
        v
Satellite-time feature matrices
```


## 6.1 Raw UBX Data Structure

The raw receiver outputs are organized as:

```text
site–date–hour–UBX message type–JSON file
```


Example:

```text
S1/

└── 2026-05-20/

    └── 13/

        ├── RXM-RAWX/
        ├── NAV-SAT/
        ├── NAV-PVT/
        ├── NAV-POSECEF/
        ├── NAV-CLOCK/
        └── NAV-DOP/
```


The raw dataset contains the original UBX messages, including:

- `RXM-RAWX`
- `NAV-SAT`
- `NAV-PVT`
- `NAV-POSECEF`
- `NAV-CLOCK`
- `NAV-DOP`


JSON files are named according to the receiver timestamp:

```text
yyyy-mm-dd HH-MM-SS.json
```


`RXM-RAWX` and `NAV-SAT` provide the main satellite-level observations used in the preprocessing pipeline.

- `RXM-RAWX` provides raw GNSS measurements, including pseudorange, carrier phase, Doppler, and C/N0.
- `NAV-SAT` provides satellite geometry information, including satellite ID, visibility status, C/N0, elevation angle, and azimuth angle.


## 6.2 Structured GNSS Files Generated by Process-1.py

The first processing stage converts raw UBX messages into structured GNSS files:

- **observation**

  Contains raw GNSS measurements extracted mainly from `RXM-RAWX`.

- **satelliteInformation**

  Contains satellite geometry and quality information extracted mainly from `NAV-SAT`.

- **pvtSolution**

  Contains receiver positioning-related information generated from `NAV-PVT`, `NAV-POSECEF`, `NAV-CLOCK`, and `NAV-DOP`.


These files are used as inputs for the second processing stage.


## 6.3 Satellite-Time Feature Matrices Generated by Process-2.py

`Process-2.py` uses the structured GNSS files to extract satellite geometry information and perform satellite-geometry-based alignment between monitoring sites.

The aligned observations are converted into satellite-time feature matrices.


The matrix format is:

```text
Satellite ID × Time epoch
```


where:

- rows represent satellite identifiers;
- columns represent continuous 1-second epochs.


The generated matrices contain GNSS features such as:

- C/N0;
- pseudorange;
- Doppler;
- carrier phase;
- elevation angle;
- azimuth angle.


Missing or invalid observations are preserved during processing and represented as `NaN` to maintain the original observation status.
